# 项目问题发现器

点击顶部“移动访问”后的“项目巡检”进入中间工作区。左右两侧仍使用现有会话列表和文件工具。项目从会话库中的单个会话模板添加，使用其工作目录、环境和 agent。支持 Windows、WSL 和 Linux SSH 的 Git 画像与静态巡检；AI 巡检、规划和实施目前仅有本地 Windows、OpenAI 后端 Codex 的强制隔离适配。其他环境或 agent 会显示不支持原因并禁止启动对应阶段，不会自动替换 agent。远程 Windows SSH 尚不支持。

## 开始巡检

点击“添加项目”选择有工作目录和 agent 的会话模板；不启动原模板中的初始命令。系统从 Git 中建立项目画像并建议 5–10 个负责人。编辑名称、路径、关注点和周期后确认负责人；只有已确认且启用的负责人会执行。

新项目默认使用模板 Agent AI，旧项目保留原设置。可在巡检设置中切换源码静态规则，静态检查不会调用模型。检查结果是待复核的潜在问题。使用受支持的 AI 执行器时，巡检使用隔离的只读代码快照和结构化输出。敏感路径、二进制和过大的文件会排除；预算或文件上限导致的覆盖不足会显示在记录中。已修改但未提交的代码不会成为 Git 巡检基线。

来源模板配置保存为快照，修改或删除模板不会自动影响项目。在设置中可以为巡检、规划、实施分别选择其他模板覆盖 agent 配置，项目目录与连接不变；模型、环境变量随 agent 配置保存。点击“重新关联来源模板”主动更新来源配置：相同仓库保留历史并更新快照，不同仓库添加独立项目。来源更新不清除已保存的阶段覆盖。

可手动巡检、启用周期巡检和提交变化巡检。周期巡检检查完整负责范围；提交变化巡检尝试包含变更文件及其传递依赖，无法可靠分析时回退为完整范围；远程环境目前使用完整负责范围，避免漏掉依赖影响。没有影响的负责人记录为跳过。并发、超时、失败退避及错过周期的处理由设置控制；重启前未结束的任务显示为中断，可手动重试。

Token 限制用于约束输入范围及检查返回的用量，不是模型服务的硬计费上限。用量不可得的失败任务单独计数，不按零用量计算。

## 从问题到修复

1. 查看问题的 Git 版本、位置、原文证据、置信度和反证。模型猜测不会自动标为已复现。相同根因跨负责人去重；可忽略、暂缓或撤销决定，保留审计记录。
2. 单独批准规划后，创建新的 Codex Plan 会话，强制只读并写入完整证据。界面切换至该会话；完成的方案保存到问题详情，重启后可恢复原线程。
3. 审阅方案并单独批准实施，才会创建独立 Git 工作树和实施会话。实施会话不能通过调整权限切换为原仓库写入。
4. 实施完成后审阅最新差异，包括新增文件，再执行验收。主进程在工作树内运行项目的 `pnpm test`，有 `build` 脚本时也运行构建；项目依赖需要在该工作树可用。缺少测试脚本、依赖、测试失败或差异发生变化都会阻止合并。
5. 验收通过后仍需单独批准合并。原仓库必须干净、仍位于审批时的分支和基线；使用 fast-forward 合并，不自动推送。
6. 合并后执行复检。只有覆盖充分且满足已知静态规则的检查能自动关闭对应问题；AI 未再次报告或检查不完整会保留复检风险。源码复检通过不代表 Electron、业务或设备运行时已经验收。

巡检数据和审批关联存放在 Electron `userData` 的独立 SQLite 数据库，实施工作树也存放在 `userData`。失败操作保留记录和工作树，避免丢失待审查的修改。不要直接删除正在使用的工作树或修改数据库来绕过审批。

后台发现新问题或风险升级时可合并发送桌面通知；前台查看时不重复弹出。通知开关位于巡检设置。
